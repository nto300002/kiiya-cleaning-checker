## 位置づけ

本書は本番MVPの画面契約を示す。入力・送信・保存の成否はAPIが返す状態に従い、画面遷移だけで完了扱いにしない。認証、権限、保存期限、報告版の規則は[要件定義](requirements.md)、[API設計](api-design.md)、[状態遷移](state-transitions.md)に従う。

トイレ・シャワーは個別の番号・性別・位置を選ばない。対象数0なら当日のチェック一覧から除外する。シャワーだけ対象数と実施数を表示し、トイレは対象数のみ、洗面台は全箇所清掃として表示する。個別の場所を数から推定しない。

客室を一室も選ばない場合はS03の客室番号・チェック・最終確認を表示しない。全室「連泊（アメニティのみ）」ならアメニティセットは表示し、ベッドメイキング・部屋掃除のカードは現在対象から外す。客室ゼロ件なら客室向け3作業とも現在対象から外す。いずれも共用部作業と休憩回答などの必須入力は表示・判定する。

選択客室の各チェック項目には作成者向けの「不備を登録」を置き、客室・項目・内容を確認して記録する。登録済み不備には状態と「解消済みにする」を表示する。解消後は対象チェックと職員最終確認を未確認へ戻し、作成者が再操作する。備考を選ぶ場合は共通の備考欄へ書き、不備として登録しなければその文面だけで報告を止めない。他の職員には状態を閲覧させ、登録・解消操作は出さない。

開始・完了の再操作と時刻修正は、当日の担当職員に対応するログイン済みの作成者だけが操作できる。S03の完了済み作業カードには「再開」を置かず、「時刻編集」と無効化した「完了」を表示する。別の職員は履歴を閲覧できるが修正できない。修正前後の値・操作者・日時をアーカイブ詳細に表示する。

### S02 トイレ・シャワーのドラムピッカー

2026-10-13に提供された操作動画をUIの参照とする。動画ではトイレとシャワーに縦方向のホイールが1つずつあり、中央の選択値を大きな濃緑色の文字で示し、前後の候補を上下に薄く表示する。各カードにはグループ名、最大箇所数、「上下にスワイプして箇所数を変更」の案内がある。

- トイレは`0箇所・1箇所・2箇所`、シャワーは`0箇所・1箇所・2箇所・3箇所`を、それぞれ独立して選ぶ。数値は個別の場所を指さない。
- ホイール上を上下にスワイプすると候補が縦に動き、操作を終えた時点で最も近い有効な整数値を中央に揃える。中央の値を選択中の対象数として表示・保存し、上下の候補は選択状態として扱わない。動画で示された中央と前後の候補の視覚的な区別を維持する。
- 上限・下限を越えて循環させない。トイレとシャワーの操作は互いの値を変えない。戻る・再表示時は保存済みの対象数を中央に復元する。新規作業の初期値はトイレ2、シャワー3とする。
- 値を変更したら作業の`targetCount`を更新する。変更前の進捗が新しい対象数に適合しない場合は再確認を促す。シャワー実施数が対象数を超える値は保存しない。トイレに実施数入力はない。対象数0のグループはチェック一覧、報告可能判定、報告、履歴の現行対象から外す。
- スワイプを使えない場合にも値を選べる操作方法と、読み上げ時にグループ名・現在値・選択可能範囲が分かる表現を設ける。見た目だけで値を判断させない。

## 主な遷移と日付変更

`S00 → S01 → S02 → S03 → S05 ↔ D00 → D01 → S06`。S01の作業開始成功がS02以降の入口条件であり、未開始の復元下書きもS01に戻す。客室ボタンはS03内の表示を切り替え、画面遷移しない。S03の完了済み作業からD02を開ける。S03からS02へ戻って対象を変更できる。S01またはS03からS07、S03またはS07からS10、S07からS08→S09へ進む。

日本時間で日付が変わると当日の画面は新規作業に切り替え、前日の作業は削除せずアーカイブへ移す。アプリを開いたまま日付をまたぐ場合、閉じて翌日開く場合、オフラインで未同期の入力が残る場合を検証する。前日の未同期入力は保持し、日付を新しい作業へ書き換えない。過去日の報告では作業日を示して再確認する。

## マスタ変更画面の操作

S10では承認申告・承認者氏名、通知結果、編集者、候補の差分と完成版、確認者、適用予定日時を段階ごとに表示する。承認者本人のアプリ操作は求めない。確認ボタンは候補の編集に参加していない職員だけに提供し、サーバーでもIDを照合する。確認後の編集には別の職員による再確認を求める。通知済み申請は申請日時順に表示し、競合時は最新マスタとの再確認を促す。適用前は申請者またはIT担当者が理由を入力して取り下げられる。過去記録が参照するマスタ版は維持する。
