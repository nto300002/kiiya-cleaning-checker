# KIIYA見落としチェッカー 画面構成・画面遷移（担当者確認用UI）

更新日: 2026-10-09

## 1. この文書の位置づけ

担当者に操作の流れを見せるため、初回のフロントエンド試作で用意する画面と遷移を確定する。画面上のログイン、保存、Chatwork送信、通知、PDF生成は**デモ表示**とし、実サービスへの接続は後の実装で行う。デモデータと操作結果は本番記録として扱わない。後から追加された[Notionのヒアリング後の修正](https://app.notion.com/p/3ecffab34d9680aaa118daf53620bb35)と添付写真を優先する。

画面はスマートフォン縦向きを基準にする。開始時点から「今どこにいるか」「次に何をすればよいか」「未完了はどこか」が分かる構成にする。各画面の文言は[要件定義](requirements.md)の決定事項に従う。

## 2. 画面一覧

| ID | 画面 | 見せる内容・主要操作 |
| --- | --- | --- |
| S00 | ログイン | Googleでログインする入口。試作ではデモ開始ボタンで代用し、実認証は行わない。 |
| S01 | 今日の作業・開始 | 作業日、固定の予定開始時刻9:55、本日の担当職員、スタッフ人数1〜5人、人数分の氏名入力・共有候補。設定への入口。 |
| S02 | 清掃範囲の選択 | 203〜206号室、男・女トイレ、左・中・右シャワーを選択。客室ごとに大人・子どもの人数と通常清掃／連泊（アメニティのみ）／連泊清掃を入力。洗面台3か所とラウンジは常に対象。 |
| S03 | 全体チェック | 客室カードに定員・ベッド構成・宿泊人数・作業種別を表示。客室・ラウンジ・追加4箇所は各カード、トイレ・シャワー・洗面はグループの開始ボタン、担当者、完了、開始・終了時刻を表示。3グループの実施箇所数はプルダウンで入力。 |
| S04 | 客室詳細チェック | 客室だけ詳細へ進み、担当者、大人・子ども、作業種別、種別別のチェック、備品数と設置場所を扱う。通常清掃は人数分の枕セット、連泊清掃は人数分の枕再セットを必須チェックとし、連泊（アメニティのみ）には枕の項目を出さない。休憩、備考、トラブル、写真も編集できる。 |
| S05 | 報告結果 | 対象箇所、客室の作業種別・備品数と設置場所、箇所別開始・終了時刻、担当者、休憩、備考・トラブル、PDF／Markdown切替、プレビュー、下部に「編集する」「報告」。 |
| D00 | 本文編集 | 「編集する」で開く。テキストを編集し、キャンセルで破棄、OKでプレビュー本文へ反映。送信版は作らない。 |
| D01 | 送信確認ダイアログ | S05の「報告」で開く。送信先・形式を再確認し、「キャンセル」または「完了」を選ぶ。過去日付なら注意文を表示。ダイアログは独立ページにしない。 |
| S06 | 報告結果の状態 | デモ用の「送信済み」「送信失敗」「結果不明」を切り替えて表示。送信済み後の修正・再送は新しい版として見せる。 |
| S07 | 設定 | アーカイブ閲覧へのリンク、ChatworkのルームID入力と取得したルーム名、Markdown送信方法。IT担当者向けの接続管理はデモ表示で区別する。 |
| S08 | アーカイブ一覧 | 過去日の作業を一覧表示。下書き、未送信、送信済み、結果不明が判別できる。 |
| S09 | アーカイブ詳細 | 過去の対象箇所・チェック結果、報告版・送信状態を表示。対象から外した箇所は表示しない。期限内の未送信記録は再開できる見た目にする。 |
| S10 | マスタ変更 | 設備・清掃項目・客室情報の変更候補、承認取得の申告、KIIYA側スタッフ名と自分以外の職員名を自由入力。通知状態と本人向けアラートのデモ表示。 |

共用部の詳細画面は作らず、S03の担当者選択と完了チェックで記録する。トイレ・シャワー・洗面は選択済みの場所数を上限とする件数プルダウンを持つ。客室廊下・階段・玄関・洗面周り床もS03に追加する。休憩・備考・トラブルは作業記録全体の入力として扱い、S03とS04から同じ値を編集できる。S10は管理機能の**大まかな画面**までとし、実際の承認・通知処理は試作範囲に含めない。

## 3. 主な画面遷移

```mermaid
flowchart TD
    S00[ログイン S00] --> S01[今日の作業・開始 S01]
    S01 --> S02[清掃範囲の選択 S02]
    S02 --> S03[全体チェック S03]
    S03 -->|対象を変更| S02
    S03 -->|客室| S04[客室詳細 S04]
    S04 --> S03
    S03 -->|必須項目が揃う| S05[報告結果 S05]
    S05 -->|編集する| D00[本文編集 D00]
    D00 -->|キャンセル・OK| S05
    S05 -->|作業内容を修正| S03
    S05 -->|報告| D01{送信確認 D01}
    D01 -->|キャンセル| S05
    D01 -->|完了・デモ| S06[報告結果の状態 S06]
    S06 -->|修正して新版を作る| S03
    S06 -->|今日の作業へ戻る| S01
    S01 --> S07[設定 S07]
    S03 --> S07
    S07 --> S08[アーカイブ一覧 S08]
    S08 --> S09[アーカイブ詳細 S09]
    S09 -->|期限内の未送信記録を再開| S03
    S03 --> S10[マスタ変更 S10]
    S07 --> S10
    S10 --> S03
```

| 場面 | 遷移・画面上の扱い |
| --- | --- |
| 入力途中 | S04からS03へ戻っても、担当者・大人と子ども・作業種別・チェック・休憩・備考・トラブルのデモ入力を保持する。S03からS02へ戻って清掃対象を変更できる。 |
| 対象変更 | 外した箇所のチェックは内部のデモ状態に残す。S05とS09では対象箇所だけを表示し、S04の共通備考欄で変更理由を記入できる。 |
| 報告可能条件 | 各箇所／グループの担当者・開始終了時刻・完了、3グループの実施件数と選択件数の一致、客室の種別別必須チェック・人数、休憩回答が揃うまで、S03の「報告結果画面へ進む」は無効。問題が見つかった項目も確認済みにでき、共通トラブル欄へ記入する。 |
| 箇所別時刻 | S03の各箇所または3グループの「開始」で実開始時刻を記録し、「完了」で実終了時刻を記録する。予定開始9:55とは分ける。報告プレビューに両時刻を表示する。 |
| 本文編集 | D00のキャンセルは編集を破棄し、OKは編集後の本文をS05へ反映する。どちらも送信版を作らない。 |
| 「報告」 | S05の「報告」はD01を開くだけ。キャンセルでは送信しない。実製品では初回押下時刻が1週間の起算点になることを説明文で示す。 |
| 「完了」 | D01の「完了」でS06へ進む。試作では送信成功・失敗・結果不明を切り替えて見せ、実際のChatwork投稿は行わない。 |
| 日付変更 | 翌日のS01は空の新規作業として表示し、前日の記録はS07→S08から閲覧するデモを用意する。 |
| 過去日の報告 | S09から再開してS05へ進む場合、D01に「過去の日付の報告」を明示する。 |

## 4. ナビゲーションと表示上の約束

- 作業中は上部に「開始 → 対象選択 → チェック → 報告内容」の現在位置を表示する。前の画面へ戻れる。
- S03には「未完了の場所」と休憩の未回答を先に見せ、完了した場所と区別する。客室には定員・大人／子ども・3種類の作業、共用部には実施件数と時刻を表示する。S04には客室番号を固定表示し、一覧へ戻る操作を置く。
- 設定とアーカイブは主作業とは別の入口にまとめる。S10はS03とS07から開けるが、試作では変更を保存・適用しない。
- デモの入力値、氏名、Chatworkルーム名は架空のサンプルと明示する。実際のrid、認証情報、職員の実名を埋め込まない。
- 実送信と誤解されないよう、D01とS06に「デモ：Chatworkには送信されません」を常に表示する。

## 5. このUI試作の完了条件

1. S00〜S10とD00・D01をスマートフォン幅で閲覧でき、上の主な遷移をクリック・タップで辿れる。
2. 氏名入力、清掃対象、客室の大人・子どもと3種類の作業、共用部の簡易完了と3グループの件数プルダウン、休憩、報告形式を操作でき、備考・トラブルに画像を添付できる。画面を往復しても値と画像が残る。
3. 未完了時は報告結果へ進めず、完了時に進めることが画面上で分かる。
4. 対象外箇所は報告結果とアーカイブ詳細に表示されない。複数人担当、追加4箇所、箇所別時刻、人数別の備品数と設置場所が見える。
5. D00のキャンセル／OKで本文の変更を確認でき、送信版が作られない。
6. 送信確認のキャンセルと「完了」、送信済み・失敗・結果不明の表示をデモ操作で確認できる。
7. 設定からアーカイブへ移動でき、翌日の新規画面と前日の記録を切り替えて見せられる。
8. 実認証・API・Chatwork・PDF生成を呼ばず、どの画面もデモであることが分かる。
